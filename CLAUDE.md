# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

This is `git-repository-foss-template`: a batteries-included **template repository**, not an application. It exists to be cloned as the starting point for new FOSS repos, so it ships only tooling/config — pre-commit hooks, a changelog generator, and a spelling dictionary — plus docs describing how to use them. There is no source code, build system, or test suite to run.

Workflow model is [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/#summary) + [Git Flow](https://about.gitlab.com/blog/what-is-gitflow/#what-is-gitflow); commit messages and branch names are sanity-checked by hooks (see below).

## Commands

Run all pre-commit hooks against the whole tree (not just staged files):

```bash
pre-commit run --all-files
```

Regenerate `CHANGELOG` from conventional commit history via git-cliff (containerized, no local install needed):

```bash
docker run -t -v "$(pwd)":/app/ "orhunp/git-cliff:${TAG:-latest}"
```

There is no build, lint, or test command beyond the above — `pre-commit` *is* the lint/check step for this repo.

## Architecture / how the pieces fit together

- **`.pre-commit-config.yaml`** wires three hook sources together:
  - `pre-commit/pre-commit-hooks` — generic hygiene (trailing whitespace, EOF fixer, YAML/JSON validity, large-file guard, executable/shebang check, AWS credential leak detection).
  - `streetsidesoftware/cspell-cli` — runs twice: once as a normal `pre-commit` stage hook (checks file contents against `cspell.json`), and once as a `commit-msg` stage hook (checks the commit message itself).
  - `compilerla/conventional-pre-commit` — a `commit-msg` stage hook that enforces Conventional Commits format, with `--strict` and a fixed scope list: `feat, fix, refactor, tests, build, ci, changelog, docs, perf`. **Any commit added to this repo must use one of these scopes**, e.g. `feat(scope): message`.
  - Hook install types are pinned via `default_install_hook_types: [pre-commit, commit-msg]` — both stages install when someone runs `pre-commit install`.
- **`cspell.json`** is the project dictionary. `words` is the allowlist for terms cspell would otherwise flag (tool names, project-specific jargon, abbreviations). `ignorePaths` excludes generated/vendored content (`CHANGELOG.md`, `node_modules`, `.venv`, etc.) from spell-checking. When a commit or file legitimately introduces a new proper noun/term that trips cspell, add it to `words` rather than working around the check.
- **`cliff.toml`** configures git-cliff's changelog generation: it parses commits as Conventional Commits (`require_conventional = true`, `filter_unconventional = true`), buckets them into changelog sections via `commit_parsers` (feat→Features, fix→Bug Fixes, doc→Documentation, perf→Performance, refactor→Refactor, test→Testing, chore/ci→Miscellaneous Tasks, revert→Revert, everything else→Other), and silently skips release/dependency/PR-bump chore commits (`chore(release): prepare for`, `chore(deps...)`, `chore(pr)`, `chore(pull)`). The Tera template in `[changelog].body` controls the actual Markdown layout emitted per release. Note the output file is literally named `CHANGELOG` (no extension) at the repo root, matching `cspell.json`'s `ignorePaths` entry for `CHANGELOG.md` loosely — check the actual filename before assuming either name.
- **`.github/PULL_REQUEST_TEMPLATE.md`** is adapted from Angular's PR template, genericized for this project (the "angular.dev" checkbox was replaced with "Infrastructure / tooling changes").
- **`docs/CONTRIBUTING.md`** summarizes the contributor-facing workflow (hook install, commit format, changelog regen); **`README.md`** covers the same ground for repo consumers/maintainers. There is no `src/` — this template is config-only.

## Working in this repo

- Prefer editing config files (`.pre-commit-config.yaml`, `cliff.toml`, `cspell.json`) over adding new tooling — the whole point of the template is staying minimal.
- Never hand-edit `CHANGELOG` — it's generated by git-cliff from commit history.
- Any new commit message must satisfy both cspell (commit-msg stage) and `conventional-pre-commit`'s strict scope list at once.
